# App Shell

The screens the admin uses. This file does not point at stage folders. The stack lives in `stack.md`.

## Club

The admin describes the club in plain language, or edits sports, courts, hours, restrictions, and the fill policy. The screen shows the current base before any message is written.

## Messages

The admin reads the greeting, the invitation, and the Flow screens. Nothing is published until they approve on this screen.

## Players

The admin uploads an Excel file or a CSV. The screen shows the roster and any row that failed.

## Sends

The admin sees who receives the message, when it goes out, and whether the test arrived. The live schedule starts only after they approve.

## Agenda

The standing screen after setup. It shows each court by hour, who is booked, and which hours are free. The admin can assign a player in plain language. Choices that players make in WhatsApp land here. The fill policy from the club identity decides which free hour is offered next.
